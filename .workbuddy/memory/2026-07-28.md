## 修复环路执行卡死问题

### 问题
环路中所有节点互相依赖，前驱计数值都 > 0，导致 `BuildDependencyGraph` 后将环节点全部阻塞，执行引擎只跑完 Start 节点就卡住（1/5）。

### 修改
5. **Editor/FlowEditor/Core/FlowChartExecutionEngine.cs** — `BuildDependencyGraph()`
   - 新增 DFS 回边检测：0=未访问, 1=递归栈中, 2=已完成
   - 被判定为回边的连线**不计入前驱计数**（但仍保留在后继列表中）

## 修复环路只循环两次就退出

### 问题
第二轮循环时，`remainingPredecessors[回边目标]` 被重置为初始值 1，回边信号使其降为 0（不是负数），走了正常调度路径而非环路重置路径。正常调度不会重置环节点的 TCS，导致 `WaitForCompletionAsync` 误判全部完成退出。

### 根因
依赖 `remaining < 0` 检测回边触发不可靠——首轮 remaining 从 0 降到 -1 触发重置，但重置后 remaining=1，次轮回边信号使其降为 0 而非负数。

### 修改
7. **Editor/FlowEditor/Core/FlowChartExecutionEngine.cs**
   - `DetectBackEdgeTargets()` 重命名为 `DetectBackEdges()`，返回 `HashSet<(string Source, string Target)>` 回边对
   - `RunNodeAsync()` 新增 `backEdges` 参数，后继遍历时**先检查当前边是否为回边**：
     - **是回边** → 直接执行环路重置（不递减 remainingPredecessors）
     - **非回边** → 正常递减前驱计数，降为 0 则调度
   - 同时修复了 TCS 竞态：`myTcs.TrySetResult()` 移到后继处理之后，确保重置创建的新 TCS 先入 `activeCompletions`

## 重构：分离 DAG 和环路执行器

### 问题
把循环硬塞进 DAG 执行模型导致复杂度爆炸：TCS 替换、前驱计数重置、activeCompletions 同步、竞态条件——每修一个 bug 冒出新的。

### 方案：按场景分离执行器
- **有环路** → `ExecuteCyclePathAsync()`：路径追踪，单队列，无 TCS/无竞态
- **无环路** → `ExecuteDagAsync()`：依赖驱动异步（原逻辑简化，去掉所有环路处理代码）
- **调试模式** → `ExecuteSequentialAsync()`：拓扑排序 + while 循环（已有）

### ExecuteCyclePathAsync 核心逻辑
```
queue = 入口节点
while queue 非空:
    node = queue.Dequeue()
    if node.remaining > 0: queue.Enqueue(node); continue  // 前驱未完成
    执行 node
    foreach 后继:
        if 回边: remaining[后继]=0, 入队  // 无条件循环
        else: remaining[后继]--, 降为0则入队
```
无 TCS、无 activeCompletions、无 cycleMemberSets、无竞态。
