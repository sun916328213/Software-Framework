# 视觉工具扩充计划

## V3：商业视觉能力路线图——旋转/缩放/掩膜匹配优先

**状态：V3首批OpenCV有界离散旋转/等比尺度搜索已实现，其余M0–M8仍为计划。** 已补离散漏检后的降采样位置候选与局部角度采样（0.5°提议/0.1°精化）；新建Controls模板工具默认开启角度范围，旧配方不迁移。用户掩膜、完整金字塔/连续精化、HALCON补齐和非单位Scale下游跟随未完成。详见[模型能力现状](MODEL_CAPABILITIES.md)及验证记录。本节替代下文V2中“OpenCV旋转/缩放另评估”“暂不扩展缩放”的排期限制，但不改变现有运行时守卫；守卫必须在对应新能力真实验收后才调整。V2及其历史验收记录保留，不把历史通过数量算成本规划的新证据。

### 0. 目标、范围及不变项

目标不是复制商业软件界面或凑工具数量，而是逐项达到“能建模、能编辑、能组合、能保存重开、能诊断、精度与节拍有证据”的工业视觉闭环。优先对标定位匹配，再补双后端基础处理、计量、标定、对齐检测和识别；不承诺OpenCV实现等价于PatMax或HALCON形状匹配。主线限定2D传统视觉，保留现有AI能力；3D、线扫拼接及独立AI训练平台需另立范围，不以本计划宣称覆盖所有商业产品功能。

- 固定当前.NET9/C#13、WPF/Prism、OpenCvSharp4.11.0.20250507及HALCON23.11；不以升级依赖替代功能实现。
- Tools负责算法及模型；Core只放必要的坐标/结果/能力契约；FlowNode声明参数和端口；Controls拥有唯一完整编辑器、目录、会话及文件协调；Workbench保持薄宿主。
- 继续用原Session、参数DTO、快照/revision、结果归属、FlowEditor执行/连接及文件机制；不创建平行节点框架、执行器、绑定表、模板会话或工程格式。
- 继续显式选择图像/结果来源；缺失不变成0/false/原点；运行/取消后不沿用旧结果。下游不得把Scale忽略后当刚体处理。
- FlowNodes.Workbench后续可选择全部、部分或不加入Vision；展示与文档恢复分别装配。MachineApp不修改、不构建、不验证。
- 不接真实设备、安装Runtime、解除Skip、加载未授权模型或强停原生调用。Native正向验收依赖用户提供的HALCON Runtime/License和许可样本。

### 2. 对标方法与官方依据

对标分四层：①工具族覆盖；②参数/结果/交互是否完整；③同一数据集的定位、计量、误检漏检及资源表现；④现场部署和维护。官方文档只能证明公开功能或算子语义，不能证明本项目已达到其精度或速度。

本次实际核查：

1. HALCON23.11 [create_scaled_shape_model](https://www.mvtec.com/doc/halcon/2311/en/create_scaled_shape_model.html)：训练域决定模型区域；默认参考原点是域的重心，可另设原点；模型包含金字塔、旋转和尺度。
2. HALCON23.11 [find_scaled_shape_model](https://www.mvtec.com/doc/halcon/2311/en/find_scaled_shape_model.html)：输出位置/角度/Scale/Score；搜索图domain控制模型参考位置的搜索空间，不等同逐像素屏蔽；边界、重叠及亚像素有独立语义。自定义模型原点与搜索域约束之间还有特殊规则，必须实测，不能靠常识推断。
3. OpenCV4.11 [templmatch.cpp](https://github.com/opencv/opencv/blob/4.11.0/modules/imgproc/src/templmatch.cpp)：掩膜尺寸必须与模板一致，支持8U/32F及明确通道条件；源码存在SQDIFF、CCORR、CCOEFF系列掩膜路径。
4. 同版本[官方教程源码](https://github.com/opencv/opencv/blob/4.11.0/doc/tutorials/imgproc/histograms/template_matching/template_matching.markdown)仍写仅两种方法接受掩膜，与源码不一致。因此以固定部署二进制的可执行回归决定开放组合，不能照搬教程限制，也不能因源码存在就认定所有退化输入安全。
5. Cognex VisionPro10 [2D Tools清单](https://docs.cognex.com/vpromx_1000/web/EN/visionpro/Content/Topics/release-information/2D-tools-in-this-release.htm)：核实PMAlign/PatMax、Caliper、Histogram、Find/Fit、Fixture、标定、单双图处理及OCR/OCV工具族，且明确区分有无QuickBuild界面的工具。该资料为10版本工具清单，不称最新版本。

本次Cognex PatMax细节页和产品页请求返回429，OpenCV渲染文档403；通过OpenCV官方仓库源码完成后端核查。未核实的Cognex具体掩膜/形变参数不写成已确认对标事实，后续需许可文档或实机验证。

### 3. 模板匹配首版能力规格

#### 3.1 必须明确区分的概念

- **模板有效掩膜**：模板局部坐标中的有效像素/模型特征，排除背景、日期、反光等不稳定部分。首版二值0排除/255参与；非零导入规范化，保存规范值；软权重掩膜后置。
- **搜索ROI/搜索位置掩膜**：限定候选参考点出现的位置。明确“参考点在域内”与“完整目标都在域内”两种规则；不能把HALCON ReduceDomain当作通用逐像素忽略搜索图的证明。
- **检测排除区/缺陷屏蔽**：后续差分检测中的排除区域，不能用模板训练掩膜冒充。搜索图坏点逐像素忽略如需支持，单独评估两后端可实现性和计分分母。
- **遮挡容忍**：目标的模型特征在运行图中缺失，与训练掩膜不同；必须以遮挡样本测误检/漏检，不能宣称“有掩膜就抗遮挡”。

#### 3.2 参数、结果和状态

| 项目 | 首版要求 |
|---|---|
| 运行模式 | OpenCV保留原固定方向/尺寸路径，新增明确的旋转/等比缩放模式；不暗改旧文件行为 |
| 搜索角度 | 起始/范围或等价上下界、跨±180度/360度环绕；采样步长和精化策略显式或有确定自动规则 |
| 搜索尺度 | 有限正数、Min≤Max、1为原始模板尺寸；建议首个基准覆盖0.5–2.0倍，不作为所有样本/速度的无条件承诺 |
| 模板资产 | 独立模板像素、同尺寸掩膜、参考原点、有效面积、必要的训练设置和内容版本 |
| 运行控制 | MinScore、MaxMatches、重叠策略、搜索ROI、计算预算/取消；明确总预算耗尽与正常无匹配的区别 |
| 结果 | 模型参考点、几何中心（如可推导）、真实角度/Scale、原始/展示得分、变换矩阵、旋转四角/轮廓、模型及输入身份；不伪造未计算字段 |
| 分数 | 越大越好的展示约定可保留，但原始指标和换算规则清楚；不同方法/后端阈值不互认，分数不是概率 |
| 无效输入 | 空/全零掩膜、尺寸不符、有效像素过少、低纹理/零方差、非法范围、NaN/Infinity、模板退化、所有变体不可搜索均有明确诊断 |
| 多目标 | 所有角度/尺度候选统一排序和空间去重；不能每个角度各返回一份同一目标；对称模板的歧义要显式提示或采用确定规则 |
| 模型状态 | 未准备、已准备、需重建/训练、构建中、失败/取消；参数/掩膜变化使旧缓存失效，训练失败不能把旧模型当新模型执行 |

OpenCV相关系数可能为负，掩膜归一化还可能出现非有限响应；不得通过简单Clamp把数值异常变成高分匹配。有效面积与方差检查、逐候选有限性检查属于功能要求。

#### 3.3 原点和坐标

参考定义：

`p_image = p_reference + scale × R(angle) × (p_template - template_origin)`

先用独立标记图冻结像素中心、X列/Y行、角度正向及单位，再与现有Pose2D/OpenCV/HALCON转换对照。特别验证90/180/270度、非中心原点和奇偶模板尺寸，不能只看注释就认定角度符号一致。

HALCON掩膜会改变默认域重心。编辑掩膜不能无声改变用户选择的原点；训练原点、模型轮廓局部原点、返回参考位置及渲染映射必须成套处理。旧文件的中心/半像素约定保持原语义，通过明确版本迁移而非重新解释。

尺度匹配不等于缩放测量已实现：

1. 第一阶段真实报告匹配Scale，旧刚体消费者继续拒绝非单位Scale。
2. 下一阶段基准到当前图的相对映射使用 `T_current × inverse(T_reference)`，不能只乘当前Scale或只减两个中心。
3. 先限定同一直接输入的正等比缩放；复用已有AffineTransform2D/CoordinateChain经验证的能力，不另造坐标框架。Pose2D保持刚体含义。
4. 点/线/圆、搜索域、宽度和采样间隔分别规定如何随尺度变化；强度阈值不随尺度乱改。非等比缩放使圆变椭圆，禁止强当圆处理。
5. Crop/缩放图像的像素映射、畸变校正及毫米映射分阶段接入；不以图像hash相同证明坐标同源。

### 4. 分阶段工作包与门禁

#### M0：能力冻结、样本与基准（所有算法工作前置）

交付：双后端能力表、首版参数/错误/坐标规格、正负样本清单、授权条件、性能测量环境与旧文件样本。将每项标为源码已有/离线可验/需HALCON/需实图，不填笼统完成百分比。

收集至少：高纹理件、低纹理轮廓件、圆/对称件、重复阵列件；正常、缺件、遮挡、反光、模糊、亮度变化及错误相似件。训练图、调参图和留出验收图分开，同一原图的增强版本不跨集合泄漏。

门禁：冻结第一批实物样本、相机分辨率、搜索范围和目标节拍后才估工期/性能；若暂无样本，先交合成图和契约里程碑，不宣称工业能力达到商业产品。

#### M1：公共模板资产、二值掩膜和原点

在原ITemplateTool及原模板编辑会话上评估必要的可选能力扩展，不强迫无模板工具实现新接口。支持模板图上矩形/圆/多边形有效区与排除区；首版复用已有ROI几何做加减，画笔/橡皮擦作为明确后续子包。提供反选、清空、重置、透明叠加及原点十字；界面显示模板局部坐标，不写进任务搜索ROI。

模板、掩膜和原点进入原快照/revision及模型包，缓存身份包含这些内容。掩膜编辑引发结果失效与必要训练失效；关闭/取消仍等实际工作归还资源。

门禁：非矩形带孔模板、全白等价旧模型、全零拒绝、模板重取样不保留错尺寸掩膜、奇偶尺寸原点、编辑取消/只读/运行锁、文件往返和加载失败事务。

#### M2：OpenCV带掩膜旋转/缩放灰度匹配

先实现可验证的参考路径，再优化：

1. 验证原三种方法在固定4.11部署包下的掩膜行为和退化响应；只开放通过回归的方法组合。
2. 模板和掩膜成对变换，旋转补边必须排除；首版二值掩膜重采样规则明确，不能把补黑边当模板特征。
3. 用图像金字塔、粗到细角度/尺度搜索和候选精化控制成本，不把整图×全部角度×全部尺度暴力扫描包装成实时引擎。
4. 回映变换后的原点和旋转轮廓，跨尺度/角度统一NMS；细化精度先证实再显示小数位。
5. 缓存金字塔及变体，受总内存预算约束；修改模板/掩膜/构建参数即失效，不缓存无界角度×尺度笛卡尔积。记录构建耗时、搜索耗时与候选数。
6. 角度/尺度批次之间检查取消；单次Native调用不可中断时等待结束，丢弃迟到结果，不释放仍在使用的Mat。

后续M2b针对灰度相关的局限，独立评估/实施梯度方向或轮廓匹配：低纹理零件、光照/极性变化、部分遮挡和相似负样本分别评测。不能把ORB/SIFT特征点匹配当作对所有工业零件通用的PatMax替代品，也不假定当前OpenCvSharp包已包含某个contrib模块；是否增加依赖须单独确认。若该路线达不到基准，应如实限定OpenCV适用范围，让HALCON形状匹配承担已验证的场景，而非暗中切换后端。

门禁：旧模式回归不变；已知位置/角度/尺度的独立基准；非矩形掩膜背景干扰；亮度/模糊/遮挡负样本；跨尺度重复候选、对称/边界、小模板、空结果、预算与取消。

#### M3：HALCON形状匹配补齐（与M2并行推进，不以OpenCV测试替代）

沿用已有scaled shape model：

- 托管掩膜转换真实HRegion并在训练图上形成有效domain；正确设置/保存用户原点，验证掩膜孔洞和模型轮廓。
- 将当前硬编码训练设置中确有用户价值的项纳入原训练参数：训练角度/尺度范围、金字塔、极性/对比度及最小特征条件。对比度、噪声阈值等HALCON专属参数不强行和灰度相关逐字段拉齐。
- 明确训练与运行范围的包含约束；保存实际模型参数而非只相信配置文本；补运行亚像素策略、重叠、贪婪度及边界策略的可选配置。
- 优先模型级边界/超时设置；避免为了一个工具修改HALCON全局系统状态。可取消性按23.11算子真实能力实现，不用Task取消假装中断原生调用。
- 保持候选模型构建→成功交换→释放旧句柄的事务；模型被运行借用期间不替换/清理。多会话/并行运行的句柄复用必须专项确认。
- 后续M3b按样本需要评估HALCON NCC灰度匹配，与形状匹配分开声明适用范围、模型类型和分数，不为凑双后端数量无条件增加入口。

门禁分离：离线合同/UI可先交；真实训练、角度/Scale/原点、掩膜、轮廓、模型保存加载、异常清理和重复创建释放必须在授权HALCON环境执行。没授权则标Native阻塞，不自动跳过后写全部完成。

#### M4：唯一编辑器、具体节点和文件兼容

在原VisionToolEditorView/模板页上统一“取样→掩膜/原点→构建/训练→搜索预览→结果表→保存模型”操作。固定原五个主操作按钮，不重建工具列表页；后端不支持的专属设置解释并禁用，不伪装可用。

- 展示搜索ROI、模板有效区、实际模型特征、候选参考轴和变换轮廓，图层来源清晰；多候选选择不改变原结果身份。
- OpenCV.TemplateMatchNode补角度/尺度及所需输出；新增有真实参数/结果/端口职责的HALCON ShapeMatchNode，并按批次推进HALCON Blob/FindLine具体类，不加空继承壳。
- .flow保存配方/模板资产/掩膜/原点/模型引用，不保存运行结果或句柄；.visionproj仍是当前工具配置，打开不自动训练/加载Native模型。
- 复用TemplateModelFile扩展.vtemplate/.vshape版本；旧V1无掩膜视为全有效，保留旧模式/原点语义。原始.shm可能缺取样/掩膜编辑资产，应准确显示缺失而非伪造；无法证明可还原的编辑资产不能标可编辑。
- 保存与加载均事务化；错误后模型/会话/DTO/连接身份保持，参数变化使旧结果、定位基准及派生缓存按原策略撤销。

门禁：全部相关旧文件＋新文件往返、跨工具错模型拒绝、真实窗口交互/只读/宽窄布局、两个候选独立绑定、撤下页面不释放节点、结果/缓存不进入配方。

#### M5：相似变换定位与下游测量跟随

M2/M3真实输出先于本阶段。先对同一直接输入开放正等比缩放：Blob/统计搜索域，找线的路径/带宽/卡尺，找圆的候选域/半径/期望点逐项实施。

输出几何仍位于当前图像像素坐标，长度随真实图像尺寸体现，不为了匹配Scale自动除回模板尺寸；如需物体标准尺寸或毫米，由显式标定/坐标转换负责。保持原配方不写回，用本次执行快照派生几何。

门禁：模板位移＋旋转＋缩放→真实找线/找圆/Blob→测量→Tolerance→Switch→重开；参考Scale非1时相对变换正确；同hash异Crop、旧帧、缺匹配、模式开启后断线仍拒绝。镜像/非等比/透视继续拒绝，直到各自工具及坐标契约交付。

#### M6：双后端基础工具补齐与计量强化

分小批推进，参数和算法差异写进能力表，不要求输出像素或分数逐点相同。

| 批次 | OpenCV | HALCON | 闭环与门禁 |
|---|---|---|---|
| B1 格式/处理 | 审查现有Convert/Filter/Crop/IntensityTransform的ROI、位深及边界 | 补转换、滤波、裁剪、灰度变换 | 彩色/16位→显式转换/滤波→后续工具；stride、Alpha、domain、舍入/饱和 |
| B2 区域/统计 | 完善阈值、形态学、Blob、直方图编辑/结果 | 补范围/自动/局部阈值、形态学、灰度统计、颜色分割 | 分割→连通/填孔/区域交并差→面积/圆度/长宽比/灰度特征筛选→Count/判定；孔洞/有效域/Gray16真实量纲 |

#### M7：标定、对齐、差分和传统缺陷检测

- 完善N点标定矩阵方向/单位、残差与独立验证点；棋盘格标定、畸变校正和像素→毫米按完整映射实现，不用两个Scale字段代替标定。
- 图像对齐输出图像及坐标映射，规定插值/边界/有效域。先刚体/相似，再单独评估仿射/透视；标定和畸变不是Pose2D。

- OCR/OCV、读码按实际引擎/License及样本排独立子包；OpenCV不自带完整工业OCR，不默认引入新SDK/下载模型，也不把HALCON有算子等同于当前授权可用。

门禁：单位/来源错误拒绝、标定留出点误差、已知缺陷与相似干扰负样本、参考图丢失、配置重开与结果失效、有效域边界误检。

#### M8：商业化工程验收与发布

- 正负样本留出集：召回/精确率/每图误检数、定位位置/角度/尺度误差；对称件按等价姿态定义评价，不因角度等价而误报失败。

### 5. 建议验收量化方式（待M0冻结，不是已达到的指标）

- 合成姿态集建议覆盖0、±1、±15、±45、±90、180度及跨界角；Scale覆盖0.5、0.75、1、1.25、1.5、2及边界外样本；包含非中心原点、不同模板奇偶尺寸和不同缩放插值。
- 每类实物建立独立正常/异常/相似负样本及留出集；数量按误检率置信要求计算，不用少量漂亮截图证明低误检率。
- M0可先提出合成清晰样本的位置≤0.5px、角度≤0.5度、Scale相对误差≤1%的候选门槛；需按模板尺寸/纹理/对称性分组证实，不作为所有产品承诺。亚像素界面显示与测量精度不是同一件事。
- 节拍不预先许诺10ms/100ms；依赖固定硬件和搜索空间。首次基准后确定各工具及整条流程预算；超预算需缩ROI/范围/模型复杂度或调整算法路线，而不是隐藏耗时。
- 用独立生成器/手工标注或标定真值；不能用待测匹配器自己产出期望，也不能只用与实现完全相同的warp生成同构测试。

## 3. 扩充范围：16个候选工具，不做后端翻倍

下列名称是规划代号，最终稳定ToolIdentity在实施前冻结；不在本轮创建空类/空注册。一个工具支持多种明确模式，不按每个模式重复建节点。此前传统工具优先OpenCV的建议已被本版双后端矩阵覆盖：基础处理和计量按双后端补齐，纯数学/公差共用，识别按实际引擎/许可决定；不为每个模式或无意义后端副本凑数。

### E0：先补可组合性，不新增算法节点

- 工具箱保持**左侧复用FlowToolboxView**。在原单一注册源补显式功能分类元数据，建议按“图像处理/定位/测量/检测/识别/标定”分组，后端为子分组或标签；旧ToolEntry.Name、目录键、工厂和文件身份不变，不从名字猜能力。
- 为E2消费者补最小的点/线/圆/数值/布尔数据连接，复用原端口传输与文档连接；来源须记录节点、结果项、字段和单位，不能抄显示字符串或按排序行号取结果。当前Result出口存在，不等于已有这些端口的编辑/消费闭环。
- 输入缺失、失效、无候选与合法的0值/空检测分开；失效传播、迟到隔离、关闭等待沿用现有链。
- 已由R4-A1完成OpenCV FindLine两模式同输入/同直接来源单位尺度刚体准备与主链平移，R4-A2已补Hough圆心候选选择域/期望点同步跟随，继续HALCON正向与其他计量模式；原P7建议仅在此重新排入待实施范围。先不扩张到缩放、镜像或任意跨图链。
- 审查上述5个遗留候选，决定接入/作为现有工具模式/暂缓，分别记录理由，不一键全注册。

**门禁**：上游线/圆或统计值能被下游明确选择，改参/换帧/重开不引用旧结果；同图像几何与单位不被混用。只针对消费者所需能力做最小适配，不先造通用表达式语言或重构整个节点框架。E1图像转换和滤波不必等待所有E0几何工作完成。

### E2：测量与公差，新增4项（依赖E0所需数据连接）

## 4. 用组合任务验收，不仅逐工具点绿

| 场景 | 组合 | 必须核对 |
|---|---|---|
| 杂质/多料少料 | Convert→Filter→AdaptiveThreshold→Blob→ToleranceJudge | 像素与数量/面积独立预期，光照/噪声变化、有效全黑、支路输入不污染 |
| 宽度/装配间隙 | Matching→刚体定位→Caliper/FindLine→GeometryMeasure→ToleranceJudge | 不默认在二值图上做精密测量；平移/旋转、失败无旧位姿、显示/测量坐标一致 |
| 颜色有无 | ColorSegment→Blob/统计→ToleranceJudge | 红色Hue环绕、颜色干扰、颜色与灰度图显式区别；“存在检测”先用组合模板而非重复工具 |
| 缺陷比较 | Matching→ImageWarp→ImageDifference→Blob→ToleranceJudge | 参考图/目标图显式绑定，边界有效域、未对齐误差与真实缺陷分离 |
| 物理尺寸 | Calibration→Undistort/坐标映射→测量→ToleranceJudge | 校准链、单位、方向、误差；不能把px直接重命名mm |
| 标签/印字 | 定位→OCR→规则判定，另一路对齐→PrintInspection | 识别正确率与缺笔/污点召回分别统计，不混为一个“准确率” |

每个任务都必须保存.flow、关闭原宿主/会话、创建新会话重开再执行；修改上游、换图、删除节点、运行中关闭后，不出现旧结果/泄漏/假OK。离线真OpenCV、受控fake和真实SDK/现场测试分开报告。

## 5. 每个工具的交付清单

1. 冻结首期图像格式、ROI、坐标/单位、算法模式、输入输出、失败含义与非目标；先用小规模代表图验证可行性。
2. 在原Tools工程实现Parameters/Validate/Run/Result与原呈现适配；不把算法搬进ViewModel，不新增平行编辑器/执行器/插件框架。
3. 复用原属性元数据、ROI、模型、结果身份与缓存；只有卡尺剖面/直方图等确需专用呈现时增加最小组件。
4. 在单一ToolRegistration源注册一次，工具箱可搜索、添加、选择、运行；原始API与目录身份兼容。
5. 结果数值与几何均有独立预期；只对真实需求补最少测试，保留原有算法回归，不为私有转发堆测试。
6. 实际验证相关逻辑/WPF/文档往返/宿主构建及对应组合任务；如改通用FlowEditor则补该模块回归。数值容差来自算法/图像规格，不能从当前实现反算。
7. 噪声、反光/低对比、边缘截断、退化几何、空ROI、无匹配、错误模型/单位、失效/重入及释放按影响覆盖；性能记录图尺寸/ROI/线程/硬件与预热条件，不无依据写死阈值。
8. 每阶段执行后重核至少两个相关官方来源并更新实施计划、差距与证据。未经授权不接相机/生产线；实图与物理DPI/OLE鼠标验收单列。

## 6. 暂不扩张

- 不为数量新增四个形态学节点、三个同功能AI Provider节点、存在/缺料/漏装等重复包装；先提供可保存的组合示例。

- OpenCV读码后端可后续做能力/许可调研；已有HALCON读码先完善。暂不为增加后端数量引入额外OCR/推理依赖。
- 暂不做3D/点云、手眼/机器人闭环、相机硬件采集改造、在线训练、自动生成任意脚本、SPC/MES大平台或完整Docking重构。
- 真实产品缺陷类别、最小尺寸/容差、图像格式、节拍与部署硬件会改变优先级。默认以离线2D定位/测量/检测为首期，不把这些假设当已确认现场规格。
