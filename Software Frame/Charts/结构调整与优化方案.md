# WPFControls.Charts 结构调整与优化方案

> 状态：已按本方案实施（目录迁移、模型重命名、冗余 Model 移除、刷新与生命周期约定、引用与别名同步）。本文保留原始方案描述；实际现状以源码、项目配置与下方“实施结果”为准。

## 一、调整目标

将当前图表代码整理为职责明确、支持多个绘图后端的可复用 WPF 组件：

- 统一项目名、程序集名与实际目录。
- 支持 LiveCharts、OxyPlot 并存。
- 共用输入数据，隔离各图表库的具体实现。
- 消除输入类型与第三方类型的命名歧义。
- 减少没有独立职责的 Model 包装。
- 明确绑定、刷新、线程和订阅生命周期。
- 保持业务查询、数据采集和设备操作在宿主中。

本轮不追求两套后端功能完全一致，也不为了目录对称增加空层。

- 暂不建立公共 ViewModel、统一后端工厂、Runtime 或 Core 项目。
- 测试继续放在现有测试工程中，不新建测试工程。

## 三、统一项目身份，完成源码物理迁移

### 当前问题

虽然程序集已经命名为 WPFControls.Charts，但目录和项目文件仍为 Charts.Controls。LiveCharts 源码仍在 WPFControls 的 Shared 中，由图表项目通过链接源码编译，WPFControls 则通过排除项避免重复编译。

当前结构能够表达程序集边界，但源码归属不够直观。

### 修改方向

1. 将图表项目目录改为 `Software Frame/Charts/WPFControls.Charts/`。
2. 将项目文件改为 `WPFControls.Charts.csproj`。
3. 将 LiveCharts 源码实际迁入对应后端目录。
4. 将 OxyPlot 源码调整到对应后端目录。
5. 删除图表项目中的链接编译配置。
6. 删除 WPFControls 中因链接编译产生的排除配置。
7. 更新所有相关解决方案和项目引用路径。

完成后的依赖方向：

```text
MachineApp
    ↓
WPFControls
    ↓
WPFControls.Charts
    ├─ LiveCharts / SkiaSharp
    └─ OxyPlot
```

WPFControls.Charts 不得反向引用 WPFControls。MachineApp 继续只直接引用 WPFControls。

目前对 Extension 的语言功能依赖暂时保留，不在本轮顺带重构整个语言基础设施。这意味着消费者仍会获得相关传递依赖。

## 四、调整共用输入模型

### 1. 消除命名歧义

| 当前自定义类型 | 新名称 |
| --- | --- |
| LineSeries | ChartLineData |
| PieData | ChartPieData |

LiveCharts 和 OxyPlot 都有自己的 Series 类型。自定义输入再命名为 LineSeries，容易混淆业务输入与绘图对象。

建议共用输入新类型使用 `WPFControls.Charts.Models` 命名空间。

### 2. 明确模型职责

ChartLineData 表达曲线名称、数值集合和颜色。

ChartPieData 表达分类名称、数值和颜色。

共用输入模型不包含：

- LiveCharts 的 ISeries、Axis。
- OxyPlot 的 PlotModel、DataPoint。
- 控件实例。
- 数据库查询、设备连接或刷新定时器。

这两个模型仍可使用 WPF 的颜色类型。当前项目本身就是 WPF 组件，不为了完全平台无关额外增加颜色抽象。

### 3. 不扩展为通用绘图协议

当前折线输入是按索引排列的数值与可选类别标签，不是完整的任意 XY 数据模型。

本轮不顺带增加散点、时间序列、多个 Y 轴等复杂契约。后续确有需求时，再增加相应输入类型，避免一个模型承担所有图表形式。

## 五、取消冗余的后端 Model 包装

### LiveCharts

当前 ChartsLineModel 主要保存 Series、坐标轴、点大小等内部状态；ChartsPieModel 主要包装 Series 集合。这些对象由 Service 私有持有。

建议将必要状态移入对应 Service，取消没有独立职责的包装类，但必须保留原有行为：

- 已生成的曲线和坐标轴。
- 点大小、字体大小等配置。
- 增量数据操作所依赖的状态。
- 清空和重新生成数据的语义。

减少类，不等于删除状态或改变行为。

### OxyPlot

继续使用库原生的 PlotModel，不额外建立一层只包装它的自定义 Model。

每个图表控件拥有自己的 PlotModel，不能将同一个模型同时交给多个视图使用。

### 删除前的兼容检查

删除 ChartsLineModel、ChartsPieModel 前，检查：

- 是否有外部源码引用。
- 是否被持久化到配置中。
- 历史类型映射是否仍指向它们。

如果存在历史数据，必须明确迁移方案。不能删除类型后仍留下失效映射，也不能把旧展示模型直接映射成结构不同的共用输入模型。遇到无法确定的外部兼容需求时，先确认处理策略，再删除公共类型。

## 六、明确 Service 的职责

### 应当负责

- 输入数据转换。
- 后端原生 Series、坐标轴或 PlotModel 的创建。
- 与当前绘图实现直接相关的状态。
- 空数据和无效数值的处理。

### 不应当负责

- 查询数据库。
- 连接或读取设备。
- 启动采集定时器。
- 页面导航。
- 管理整个应用的语言和主题。
- 根据机型决定显示什么业务数据。

允许两套后端的服务实现不同：LiveCharts 可以保留必要的可变绘图状态，OxyPlot 可以继续创建独立模型快照。不为了形式统一，强行把两个服务改成完全相同的类结构。

## 七、基础控件暂不增加 ViewModel

### 原因

目前这些控件是折线图、饼图、仪表盘等基础展示组件，主要通过依赖属性与宿主绑定。

额外增加一层 ViewModel，可能只是重复保存 ItemSource、坐标标签、图表样式和后端绘图对象，增加同步链路，却没有增加实际职责。

### 建议的数据流

```text
宿主页面 ViewModel
    │ 数据绑定
    ↓
图表 View
    │ 调用转换服务
    ↓
后端 Service
    ↓
原生绘图模型
```

| 位置 | 主要职责 |
| --- | --- |
| 宿主页面 ViewModel | 查询、筛选、采集协调、业务命令 |
| 图表 View | 依赖属性、刷新入口、UI 线程和订阅生命周期 |
| 后端 Service | 数据转换与绘图状态 |
| 共用输入 Models | 展示所需的数据 |

图表控件不得通过设置自身 DataContext 覆盖宿主绑定上下文。

### 什么时候增加 ViewModel

以后如果增加独立的图表工作台，包含后端切换、时间范围选择、暂停与恢复、导出、多图联动、曲线选择与配置，可以为这个组合页面增加 ViewModel，而不是给每个基础绘图控件都增加一层。

## 八、规范数据刷新行为

### 当前问题

目前两套实现的更新行为并不一致：

- LiveCharts 部分控件监听了集合变化。
- 现有输入对象的普通属性并不都提供变更通知。
- OxyPlot 新控件采用快照方式，原地修改后需要显式刷新。

不能笼统地认为 LiveCharts 已支持所有输入变化自动更新。

### 本轮建立的共同约定

| 操作 | 约定 |
| --- | --- |
| 替换 ItemSource | 自动刷新 |
| 替换坐标标签源 | 自动刷新 |
| 修改样式依赖属性 | 自动应用或刷新 |
| ItemSource 设置为 null | 清空显示 |
| 原地修改输入数据 | 都可以通过 RefreshChart() 确保刷新 |

以上坐标标签和样式约定适用于提供对应属性的控件，不要求两套后端拥有完全相同的功能。

已有的自动集合更新能力先保留，不未经评估就删除。本轮先统一显式刷新入口，不强行实现完整的自动更新系统。

### 完整自动更新暂不承诺

如果以后要求所有图表都自动响应集合 Add、Remove、Reset，曲线 Value 集合替换，曲线名称与颜色变化，以及饼图单项数值变化，就需要输入模型的变更通知、嵌套集合订阅和完整的生命周期测试。

这作为后续独立任务，不在目录调整时顺带大改。

## 九、梳理 UI 线程与生命周期

### UI 线程

- 创建和更新控件、绘图模型的视图绑定，遵循 UI 线程要求。
- 后台采集先整理数据快照，再通过 Dispatcher 交给图表。
- 不允许图表读取时，后台线程同时修改同一输入集合。
- 不使用同步等待阻塞 UI。

### 订阅生命周期

对保留的自动集合订阅，明确：

1. 数据源替换时解除旧订阅。
2. 新数据源不得重复订阅。
3. 卸载时解除不再需要的订阅。
4. 再次加载时正确恢复，并刷新当前数据。
5. 卸载期间输入发生变化，重新加载后能够显示最新状态。

没有订阅的快照控件，不为了统一形式增加空的生命周期代码。

### 所有权

图表控件仅管理自己创建的绘图对象和订阅。

图表卸载不应停止宿主数据采集、释放宿主 ViewModel、关闭设备或结束业务运行会话。

## 十、暂不增加后端切换工厂

目前通过选择不同控件使用不同后端：

```text
ChartsLineView       → LiveCharts
OxyPlotLineView      → OxyPlot
```

这种方式清晰，允许同一页面混用，也能保留两套库各自的能力。

本轮不增加 IChartEngine、全局后端配置、图表工厂或统一运行时切换框架。

以后确实需要运行时切换时，再定义能够共同支持的能力范围。不能假设 LiveCharts 的多仪表盘、动画和 OxyPlot 的绘图功能可以无差别互换。

## 十一、同步业务引用与历史兼容

本轮包含输入类型重命名，不是单纯移动文件，需要检查：

- 相关 taskproj 中嵌入的脚本副本。

- 测试与使用示例。

迁移约定：

- 共用输入新类型使用 WPFControls.Charts.Models 命名空间。
- 现有后端控件和服务的 CLR 命名空间暂时保留，不批量修改。

- 涉及嵌入脚本时，只更新与本次类型变化相关的内容，不顺带修复其他业务问题。

## 十三、建议实施顺序

1. 完成物理迁移和项目路径统一。
2. 重命名共用输入模型，同步所有引用。
3. 检查兼容需求，再合并或移除冗余后端 Model。
4. 统一显式刷新入口和空数据语义。
5. 修正现有订阅与加载卸载行为。
6. 补充测试、示例和文档，执行构建与验收。

建议每个阶段分别复核引用、兼容和行为，避免目录迁移、公共类型删除和刷新机制改造同时发生后难以定位回归。

## 十四、本轮明确不做的事项

- 不新增 Core、Runtime 或更多后端程序集。
- 不为基础图表控件增加没有独立职责的 ViewModel。
- 不新增统一后端接口、工厂或全局切换配置。
- 不将图表组件扩展为设备采集或数据库查询模块。
- 不承诺两个绘图库的所有功能完全对等。
- 不在本轮顺带实现完整的自动更新、通用 XY 协议或图表工作台。

- 不为了通过验证擅自升级目标框架、降低测试断言或重写历史基线。

## 总结

一个程序集、两套后端、共用输入、按需分层；先解决边界和更新行为，不为形式增加 ViewModel、接口或工厂。

## 实施结果

### 已完成

1. 目录与项目身份：`Charts/WPFControls.Charts/WPFControls.Charts.csproj`，项目名、程序集名、根命名空间均为 `WPFControls.Charts`；两个解决方案的工程路径已同步。
2. 源码物理迁移：LiveCharts 的 Models/Services/Views 已从 `WPFControls/Shared` 迁入 `LiveCharts/`；OxyPlot 源码归入 `OxyPlot/`。图表项目不再链接外部源码，`WPFControls.csproj` 的 `Compile Remove` / `Page Remove` 已删除。
3. 共用输入重命名：`LineSeries` → `ChartLineData`、`PieData` → `ChartPieData`，命名空间 `WPFControls.Charts.Models`；属性名与序列化字段保持不变。
4. 冗余包装移除：`ChartsLineModel`、`ChartsPieModel` 删除，点大小、字体大小、Series、坐标轴、增量数据集合与饼图 Series 集合改为服务私有字段，默认值与行为不变。

6. 刷新与生命周期：三个 LiveCharts 控件提供公开 `RefreshChart()`；`ItemSource` 为 null 时清空显示（原先饼图与仪表盘会抛空引用）；`AxisX` 为 null 按空标签处理；`ChartsLineView` 的集合订阅支持替换时解除旧订阅、同一实例不重复订阅、卸载解除、重新加载恢复并刷新。
7. 文档：图表 `README.md` 与 `WPFControls/ARCHITECTURE.md` 已按新目录、命名空间与刷新约定更新。

## 后续扩展：独立 Workbench

经后续确认，新增 `Charts/WPFControls.Charts.Workbench`，用于完成上述人工验收。前文“不新增图表工作台”的限制属于原结构调整阶段；此次仅增加离线人工验证宿主，不建设生产图表工作台或统一后端切换框架。

- Workbench 仅直接引用 WPFControls.Charts，不引用 WPFControls 聚合项目或 MachineApp，不注册生产模块、不连接设备。
- MainWindowViewModel 管理页面列表、切页、重建当前页与统一释放；每页独立持有 ChartPageViewModel，管理自己的模拟数据、按钮命令、参数、计数和 DispatcherTimer。基础图表控件仍不增加 ViewModel。
- 按“后端 × 图表类型”分为六个独立页面：LiveCharts 折线、柱状、圆环、多仪表盘，OxyPlot 折线、饼图/圆环。对照页已从导航、模板和编译移除；受工具无法删除文件限制，旧 Comparison 文件暂留磁盘并在项目中排除。
- 按数据操作、样式、模拟运行分组常用按钮，诊断与生命周期操作折叠。常用修改默认自动刷新，诊断模式可关闭；按钮按空数据、运行状态、数量上限禁用。切页停止上一页模拟，取消图表挂载则不停止本页会话。
- 组件新增可继承的 ChartTheme.IsDark，将深浅模式应用到原生 Paint/PlotModel 和默认提示模板；数据重建后重新应用，不只改变宿主背景。新增 ChartsColumnService/ChartsColumnView，复用共用数值输入。

- 图表真实卸载/重载、替换 DataContext 和窗口关闭分别验证视图订阅与宿主会话所有权。
- 提供宿主主题切换、点数/间隔选择及观测读数；不把同步模型重建时间当作实际绘制性能，不把托管内存快照当作泄漏证明。
