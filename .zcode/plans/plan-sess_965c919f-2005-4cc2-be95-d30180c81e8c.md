# PropertyGrid MVVM 严格化重构计划

## 背景结论（已通过探查确认）
PropertyGrid 子系统**已经**在使用 CommunityToolkit.Mvvm 8.4.0 + Prism 8.1.97，四层目录（Models/Services/ViewModels/Views）已存在。因此本次为**重构**而非从零搭建：核心目标是**消除 MVVM 违例、补齐 DI、统一风格、清理冗余**。技术栈保持不变（不引入新包）。

**最严重的两处违例（本次重点）：**
1. `PropertyGridHost.xaml.cs` 在 View 里 `new BuiltinPropertyGrid()` 并通过 `DataContextChanged`+`PropertyChanged` 命令式编排 → TargetObject 流向是 VM→View 代码后置→Provider，违反 VM→VM。
2. `BuiltinPropertyGrid`(一个 ScrollViewer 控件) 承载反射扫描 + 构建 UI 的业务逻辑，且内部 `new PortManagementViewModel()` / `new PortDialogService()` → Service/VM 职责与 View 耦合，无 DI。

**必须保持不变的集成契约**（仅 2 处消费点，已定位）：
- `Editor/FlowEditor/ViewModels/FlowChartContainerViewModel.cs:42` → `public PropertyGridHostViewModel PropertyGridVM { get; } = new();`
- `Editor/FlowEditor/ViewModels/FlowChartContainerViewModel.cs:173` → `PropertyGridVM.TargetObject = ...`
- `Editor/FlowEditor/Views/FlowChartContainerView.xaml:639` → `<pg:PropertyGridHost DataContext="{Binding PropertyGridVM}" />`

## 实施步骤

### 步骤 1 — 新建 Service 层：`IPropertyGridBuilderService` + 实现
**新文件：`PropertyGrid/Services/IPropertyGridBuilderService.cs`**
```csharp
public interface IPropertyGridBuilderService
{
    // 扫描 [NodeProperty] 特性，产出分组 VM 树（纯业务逻辑，无 UI 依赖）
    IReadOnlyList<PropertyGroupViewModel> BuildGroups(object target, IPortConfigurable? portConfig);
    // 构建可选属性列表（供自定义输出端口绑定）
    List<string> CollectBindableProperties(Type type);
}
```
**新文件：`PropertyGrid/Services/PropertyGridBuilderService.cs`** — 把 `BuiltinPropertyGrid.ScanProperties()` 和 `AddCustomPortManagementSection()` 里收集属性的逻辑原样迁入（逻辑不变，仅搬家）。`PortDialogService` 通过构造注入传入（不 `new`）。

> 理由：把"反射扫描产出 VM 树"这一业务逻辑从 View 里剥离到 Service，View 只负责渲染。

### 步骤 2 — 重构 `PropertyGridHostViewModel`（变成真正的根 VM）
- **构造注入** `IPropertyGridBuilderService` 和 `IPortDialogService`。
- 新增 `ObservableCollection<PropertyGroupViewModel> Groups` 和 `PortManagementViewModel? PortManagement` 属性。
- `TargetObject` 的 setter 中调用 builder 构建树 + 构建 `PortManagementViewModel`（target 为 `IPortManageable` 时）。把原来 `BuiltinPropertyGrid.SetTargetObject/BuildUI` 的全部编排逻辑移到 VM。
- `UpdateExtraActions()`（反射收集 `[PropertyGridAction]` 按钮）保留在 VM。

### 步骤 3 — `PropertyGridHost.xaml` 改为纯数据绑定渲染
- 删除代码后置里的 `_builtin`/`_current`/`OnDataContextChanged`/`OnViewModelPropertyChanged`（全部业务逻辑已移入 VM）。
- `GridContainer` 改为 `ItemsControl ItemsSource="{Binding Groups}" ItemTemplate="{StaticResource PG_GroupTemplate}"`。
- 在 `GridContainer` 后追加一个 `ContentControl Content="{Binding PortManagement}" ContentTemplate="{StaticResource PG_PortManagementTemplate}"`（仅当 PortManagement 非空时显示）。
- `PG_GroupTemplate`/`PG_PortManagementTemplate` 继续从 `BuiltinPropertyGridResources.xaml` 复用（该资源字典不动，仍是渲染层）。
- 修正 `x:Class` 命名空间到 `WPFCustControl.PropertyGrid.Views`（与其它 View 统一，修复命名空间错配）。
- 删除 XAML 内重复的本地画笔 `PG_HeaderBg/PG_Accent/...`，改用共享 `ThemeColors.xaml` 的 `Color_*`（与资源字典其余部分一致）。

### 步骤 4 — 删除废弃的 `BuiltinPropertyGrid.cs` 和 `IPropertyGridProvider.cs`
- `IPropertyGridProvider` 当前**无外部引用**（`PropertyGridHost.xaml.cs` 是唯一使用者，步骤 3 后删除），`BuiltinPropertyGrid` 同理。两者职责已被 `IPropertyGridBuilderService` + XAML 渲染取代。一并删除（YAGNI，避免留下死代码/死抽象）。
- 同步删除死代码 `Services/NodePropertyDescriptor.cs`（全仓零引用，`System.ComponentModel` 遗留）。

### 步骤 5 — DI 注册：扩展 `WPFCustControlModule.RegisterTypes`
```csharp
containerRegistry.RegisterSingleton<IPropertyGridBuilderService, PropertyGridBuilderService>();
containerRegistry.RegisterSingleton<IPortDialogService, PortDialogService>();
containerRegistry.RegisterSingleton<PropertyGridHostViewModel>();
```
> 注：`WPFCustControlModule` 当前是否已加入 host 的 ModuleCatalog 需在实施时确认；若未注册，在 `Packing Machine/App.xaml.cs` 的 `ConfigureModuleCatalog` 追加（与 ControlToolModule 同列）。

### 步骤 6 — 改 Editor 接入容器（用户已确认"改 Editor 接入容器"方案）
`FlowChartContainerViewModel.cs`（已注入 `IContainerProvider _containerProvider`，改动极小）：
- `:42` → `public PropertyGridHostViewModel PropertyGridVM { get; }`
- 构造函数中 → `PropertyGridVM = containerProvider.Resolve<PropertyGridHostViewModel>();`
- `:173` `PropertyGridVM.TargetObject = ...` **不变**；`FlowChartContainerView.xaml:639` 绑定 **不变**。

### 步骤 7 — `PortManagementViewModel` 清理（VM 内部改进，不改外部契约）
- 删除 `System.Diagnostics.Debug.WriteLine` 调试输出（5+ 处）。
- 抽取重复的"按 id/PropertyName 查 binding"逻辑为本地方法 `FindBinding(id, name)`，消除 5+ 处 `FirstOrDefault(b=>b.TargetPortId==id) ?? FirstOrDefault(b=>b.PropertyName==matchP)` 重复。
- `LoadPorts` 内 `vm.ModifyBindingRequested/BindRequested/...` 的 lambda 闭包改为引用同一辅助方法。

### 步骤 8 — 统一两个对话框 VM 的风格
`InputPortEditViewModel.cs` / `OutputPortEditViewModel.cs` 当前用手写 `ObservableObject` + 手写 `RelayCommand`，与项目其余 VM（源生成器 `[ObservableProperty]`/`[RelayCommand]` + `partial class`）不一致：
- 改为 `partial class : ObservableObject`，字段加 `[ObservableProperty]`，方法加 `[RelayCommand]`。
- 移除手写 backing field 和手写 `new RelayCommand(...)`。
- `InputPortEditDialog.xaml.cs`/`OutputPortEditDialog.xaml.cs` 中 `CreateForModify` 静态工厂（无人调用）删除。

### 步骤 9 — 清理冗余目录
删除 7 个空占位文件夹 + 重复的单复数对：`Core/`、`Descriptors/`、`Providers/`、`Selectors/`、`Resources/`、`View/`、`ViewModel/`。仅保留使用的 `Models/`、`Services/`、`ViewModels/`、`Views/`。

## 完成后的四层架构
```
PropertyGrid/
├── Models/      IPropertyGridBuilderService(sealed→实际放Services), IPortConfigurable,
│                IPortManageable, IDataBindingProvider, IPortDialogService,
│                NodePropertyAttribute, PropertyGridActionAttribute(+Item)
├── Services/    PropertyGridBuilderService, PortDialogService, PropertyEditorSelector
├── ViewModels/  PropertyGridHostViewModel(根, 注入Service), PropertyGroupViewModel,
│                PropertyItemViewModel, PortManagementViewModel, PortRowViewModel,
│                InputPortEditViewModel, OutputPortEditViewModel
└── Views/       PropertyGridHost.xaml(.cs 瘦身), BuiltinPropertyGridResources.xaml,
                 InputPortEditDialog.xaml(.cs), OutputPortEditDialog.xaml(.cs)
```
**数据流（修复后）：** `TargetObject`(set) → VM 调 `IPropertyGridBuilderService` → 产出 `Groups`/`PortManagement` → XAML 双向绑定渲染。View 零业务逻辑，Service/VM 全部经 DI 容器管理，可替换可测试。

## 验证方式
1. 构建 `Editor.sln`（或 `Frame.sln` 中 Editor + WPFCustControl + Extension 子集）确保编译通过。
2. 启动 EditorDemo（`EditorDemo` 的 App 为 PrismApplication）：
   - 选中节点 → 属性面板正确显示分组卡片 + 编辑器（文本/布尔/枚举/集合/只读）。
   - 勾选 Input/Output 端口列 → `IPortConfigurable` 生效。
   - `IPortManageable` 节点 → 自定义端口管理区显示，增删/锁定/绑定上游数据正常。
   - `[PropertyGridAction]` 按钮 → 底部按钮区正确显示并可触发命令。
   - 切换不同节点 → 面板内容刷新。
3. 确认无 `Debug.WriteLine` 噪声输出。

## 不做（避免范围蔓延）
- 不引入新 NuGet 包（CommunityToolkit.Mvvm + Prism 已满足全部要求）。
- 不改 `BuiltinPropertyGridResources.xaml` 的模板定义（渲染契约保持）。
- 不实现 `Min/Max/Step` 数值范围编辑器（属新功能，非本次重构范畴；保留 attribute 字段）。
- 不改 `NodeModel`（`IPortConfigurable/IPortManageable/IDataBindingProvider` 的实现端）。
- 不把 PropertyGrid 改为 Prism Region/Navigation 导航式（它是 UserControl，由宿主 DataContext 提供 VM，此契约保持）。
