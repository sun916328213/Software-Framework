## 2. Bug 修复记录

本次测试过程中共发现并修复 3 个关键 Bug：

### Bug 1: LoopNormalizer 将退出路径误纳入循环体

- **文件**：`FlowEditor/Core/LoopNormalizer.cs`
- **现象**：`RouteToErrorPort_InCycle_TerminatesLoopOnError` 测试失败，循环未在错误时终止，跑满 100 次。
- **根因**：`CollectBody` 方法 BFS 展开时遍历了所有出边（包括 Error 端口和数据端口），导致 `done` 节点被误纳入循环体，被合成回边后重新调度循环节点。
- **修复**：在 BFS 展开中增加 `PortType.Flow` 过滤，只沿控制流边遍历，避免 Error/数据端口的退出路径被误纳入。

### Bug 2: FlowInstance 节点 Count 不递增

- **文件**：`FlowEditor/Core/FlowChartExecutionEngine.cs`
- **现象**：`TwoInstances_ConcurrentRun_Isolated` 测试失败，B.Count 为 0。
- **根因**：`ExecuteSingleNodeAsync` 中 `Count++` 只对 `NodeViewModel` 类型执行类型检查，但 `FlowInstance` 直接使用 `NodeModel` 对象，类型检查失败导致 Count 不递增。
- **修复**：改为直接对 `INodeExecutable.Count` 接口属性递增 `nodeVm.Count++`，并增加 `NodeModel` 分支处理 `CurrentRunCount` 和 `RunSequence`。

### Bug 3: 多末端回边导致循环调度无限活锁（本次更新修复）

- **文件**：`FlowEditor/Core/FlowChartExecutionEngine.cs`、`FlowEditor/Nodes/FlowControl/LoopNode.cs`
- **现象**：完整测试套件运行 15+ 分钟不结束，testhost 进程 CPU 100% 持续增长（单测试类 `JournalStabilityTests` 即可复现卡死）。历史基线 100 个测试仅需 ~1.8 秒。
- **触发用例**：`JournalStabilityTests.CapacityEviction_LatestEdgeValueStillQueryable` —— 循环体存在两条并行末端（`BOD` 计数节点与数据链起点 `A`）。
- **根因（三因素叠加）**：
  1. **多末端结构**：`LoopNormalizer` 为循环体的每个悬空末端各合成一条回边，两条并行末端 → 循环头 `L` 单轮被两条回边重新调度；
  2. **局部去重失效**：引擎 `ExecuteCyclePathAsync` 的 `rescheduled` 去重集合是**单次节点执行内的局部变量**，不同末端的回边处理互不可见 → 去重失效，循环头每轮入队 2 次，`CurrentIndex` 双倍速推进；
  3. **残留调度复活**：`LoopNode` 激活 Completed 时复位 `CurrentIndex=0`，队列中残留的第 2 个循环头调度执行时 `CurrentIndex=1 ≤ 15`，再次激活 Body → 循环复活，无限活锁。
- **修复（引擎根治 + 节点双保险）**：
  1. **引擎层**（根治）：将局部 `rescheduled` 替换为**队列级持久去重集合 `pendingBackEdgeTargets`** —— 回边调度时 `Add` 去重（同一轮内多条并行末端回边指向同一循环头时只重新调度一次），目标节点出队执行时 `Remove` 释放，跨节点持久生效；
  2. **节点层**（双保险）：`LoopNode` 新增 `_completedThisCycle` 防复活标记 —— Completed 激活时置 true；残留调度到来时不推进计数，一律再次激活 Completed 终止分支（激活边语义会剪掉 Body 出边，保证环路必然排空终止，而非重新进入 Body 造成活锁）。
- **验证结果**：`JournalStabilityTests` 单独运行 7/7 通过，253 ms（修复前同用例活锁 15+ 分钟）；完整套件 107/107 通过，636 ms。

## 7. 架构优化状态

### 7.1 已完成优化

- **模块划分**：引擎核心（Core）、节点模型（Nodes/Models）、视图模型（ViewModels）、视图（Views）清晰分层；引擎只依赖 `INodeExecutable` 执行面，不感知 ViewModel
- **编译图执行模型**：`CompiledFlowGraph.Compile()` 一次性 O(N+E) 构建邻接表/回边集合/前驱表/拓扑分层，运行期 O(1) 查表
- **错误处理**：`NodeErrorPolicy` 三级容错策略（FailFast / ContinueOnError / RouteToErrorPort）
- **日志记录**：`ExecutionJournal` 线程安全 + 容量上限 10000 条防 OOM + `TryGetLatestEdgeValue` 独立于容量淘汰
- **编辑/运行分离**：`FlowProgram` / `FlowInstance` 支持并发独立实例化
- **激活边语义**：节点 `ActivateOutput(portName)` 声明激活端口，引擎只沿激活端口调度，未声明时全放行（旧图兼容）
- **循环回边归一化**：`LoopNormalizer` 编译期自动补全悬空末端回边，画布无需手动画回边
- **环路调度防活锁**（本次）：引擎队列级回边去重 + LoopNode 防复活标记双保险（Bug 3）
- **零警告构建**（本次）：CS0693 / CS8604 / CS0414 全部清理，核心项目 0 警告

### 7.2 建议改进方向

1. **循环节点无 Body 时的语义**：当前 LoopNode 在 Body 无连线时仅执行一次无法完成循环。可考虑增加自动跳过逻辑或文档明确说明此约束。
2. **多末端回边的显式控制**：`LoopNormalizer` 当前为每个悬空末端自动合成回边。若用户希望部分末端不参与循环（如日志/监控旁路），可考虑节点级属性（如 `ExcludeFromLoop`）精细控制回边合成。
3. **性能基准自动化**：压力测试的耗时断言（< 200ms / < 500ms / < 5s）基于开发机绝对值，CI 环境波动可能产生偶发失败。可引入相对基准（与空图编译耗时比）提升稳定性。
